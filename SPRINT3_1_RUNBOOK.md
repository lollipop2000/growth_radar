# Sprint 3.1 — типы целей и бизнес-конверсия

## Status

Sprint 3.1 реализован и проверен 06.10.2026. Sprint 4–5 не начаты. Изменения используют существующие Integration config, Rules Engine, Opportunity identity, Page 360 и словарь локализации. Нет новой таблицы, destructive cleanup, crawler, scheduler, внешних запросов из расчёта или автоматического назначения типов по названию.

Техническая приёмка PASS. Пользователь вручную сохранил типы; реальный расчёт и повтор без дублей выполнены по этим назначениям. Ограничение текущего dataset: отсутствуют достижения части назначенных целей, поэтому бизнес-медианы пока недоступны.

## Goal Types

`Настройки → Яндекс Метрика → Типы целей Метрики`. Для каждой известной цели показаны имя, ID, сохранённый тип и selector. Ранее выбранные для сбора четыре цели находятся в начале списка, остальные доступны ниже. Изменение selector сохраняется кнопкой «Сохранить типы целей». Оно не меняет цели в Яндексе и не запускает jobs или пересчёт.

| Значение | Отображение |
| --- | --- |
| BUSINESS_CONVERSION | Бизнес-конверсия |
| MICRO_CONVERSION | Микроконверсия |
| NAVIGATION | Навигационное действие |
| IGNORE | Не использовать в анализе |

Хранение: `Yandex Metrika.configJson.goalTypes`, mapping ID → enum. Отсутствующий/неизвестный тип трактуется как IGNORE. Primary Goals сохраняют прежнюю выбранность для сбора статистики; она не придаёт бизнес-смысл. Названия не анализируются для автоматического назначения. При смене сайта/счётчика mapping сбрасывается; при проверке прежнего подключения назначения сохраняются только для существующих целей.

Для будущих явно запущенных отчётов набор целей — объединение прежних выбранных целей и явно типизированных бизнес-/микро-/навигационных целей. Лимит существующего отчёта: 15 разных целей. Превышение отклоняет сохранение с русским сообщением. Новых отчётов Sprint 3.1 автоматически не создаёт. Уже полученные данные не переделываются: если назначенной цели раньше не было в отчёте, её достижения неизвестны до отдельно разрешённой пользователем синхронизации.

Настройки сохраняются с existing optimistic config check и lock; активная синхронизация блокирует изменение. Публикация Rules дополнительно проверяет неизменность типов/метаданных целей после подготовки dataset. Пороги правил и Яндекс квота не меняются.

## Business Conversion

`100 × SUM(достижения только BUSINESS_CONVERSION) / SUM(visits)`.

Агрегация выполняется отдельно для каждой группы и каждого периода. Сохранённый snapshot содержит ID/имя/тип целей и достижения по каждой цели. Отсутствующее значение любой включённой бизнес-цели в любой наблюдаемой строке делает суммарную конверсию неизвестной. Пустой набор бизнес-целей и отсутствие строк не заменяются нулём. При нуле визитов rate неизвестна; известные нулевые достижения при положительных визитах дают честные 0%.

Это сумма достижений на визит, не доля уникальных покупателей: цели могут пересекаться и срабатывать несколько раз.

## Micro Conversion

MICRO_CONVERSION агрегируется независимо по той же формуле: достижения микроцелей / visits × 100. В UI показаны сумма, rate и список целей. Микроконверсии не входят в бизнес-медиану, RULE 03 или Conversion Opportunity.

## Navigation Goals

NAVIGATION показывается отдельным поведенческим контекстом с именами и достижениями. Не влияет на RULE 03, Business Conversion Rate или score. IGNORE не показывается в обычных бизнес-карточках; значения доступны в закрытом техническом блоке и исторических данных.

## RULE 03 changes

Теперь требуется: visits ≥ minVisits, явно настроенная бизнес-группа, известная business rate, известная положительная бизнес-медиана, rate ниже медианы на настроенный conversionGap. Без бизнес-целей сигнал отсутствует; показано «Для анализа бизнес-конверсии не настроены бизнес-цели Метрики».

Сохранена peer logic: минимум пять подходящих страниц того же сохранённого page type, иначе минимум три страницы сайта. В выборке только страницы с достаточными визитами и известной бизнес-конверсией. Нулевая медиана не доказывает отставание. Не используются старые combined conversion, микро-/навигационные/игнорируемые цели.

После пересчёта неподтверждённые сигналы получают isCurrent=false. Записи и их снимки не удаляются. Подтверждённые обновляются по прежней identity site/page/rule/period; DISMISSED сохраняется. Исторические снимки Sprint 3 явно помечены как расчёты по общим целям; их старые числа не переименовываются в бизнес-конверсию.

## Opportunity Score changes

Вес Conversion Opportunity остаётся 15. Используется только `15 × max(0, 1 − business rate / business median)`. Если бизнес-группа не назначена, rate неизвестна или нет benchmark, компонент unavailable и исключён из доступного веса. Не подставляется 0; остальные компоненты и нейтральный бизнес-приоритет сохранены.

Новые evidence snapshots имеют conversionVersion=2 и goalConfig. Старые формулы и evidence сохраняются для истории, а компонент общих целей в старом detail имеет историческую подпись.

## Dashboard

Общий KPI целей заменён на достижения бизнес-целей и бизнес-конверсию. При ненастроенных бизнес-целях — «Не настроено» и ссылка в Settings; при настроенных, но недоступных данных — «Нет данных». Микроконверсии не изображаются основной бизнес-конверсией.

## Page 360

Три отдельных блока: бизнес-конверсии, микроконверсии, навигационные действия. Показаны списки целей с ID/именем и достижениями; для первых двух — rate. IGNORE доступен только в техническом details. Существующие Scanner/Search/визиты/бизнес-импорт и история сохранены.

## Opportunity Detail

Новые RULE 03 карточки явно показывают бизнес-конверсию, медиану и имена бизнес-целей. В detail группы и формула оценки берутся из сохранённого снимка, не из более поздних настроек. Старые возможности доступны по прежним URL и имеют предупреждение о прежней семантике. Список возможностей использует business rate, не legacy combined value.

Регрессии Scanner/worker/Coverage/WAF/Yandex/Sprint 3 выполняются только на local fixtures. Миграции и schema drift проверяются без новой миграции; clean DB применяет существующую историю миграций.

## Known limitations

- Production назначения сделаны пользователем. Покупка, успешная регистрация, корзина и оформление заказа входят в бизнес-группу по его выбору; система не определяет смысл названий самостоятельно.
- Новые назначения не создают исторические достижения отсутствовавших в прежних отчётах целей. Неизвестные данные не считаются нулём.
- Несколько бизнес-целей могут пересекаться; sum reaches / visits не дедуплицирует покупателей или заказы.
- Назначение типа само по себе не пересчитывает Opportunities; нужно отдельное действие, история использует типы на момент расчёта.
- Сохранённые page types и минимальное число peers остаются эвристикой Sprint 3. Нулевая или недоступная медиана не создаёт RULE 03.
- Прежние ограничения: поиск только импортированной части Вебмастера, Excel пользователя ещё не загружен, uncertain Webmaster POST безопасно заблокирован. Sprint 4–5 отсутствуют.
